# Repository instructions for coding agents

Applies to every agent working in this repository — Claude Code, Codex, or
anything else. `CLAUDE.md` defers to this file; keep one authoritative copy of
each rule here rather than duplicating.

## Attribution — do not add it

Commits, pull requests, code comments, and documentation in this repository
carry **no AI attribution of any kind**. Specifically, never add:

- `Co-Authored-By:` trailers naming Claude, Codex, or any model or tool
- `Claude-Session:` or similar session/run identifier trailers
- "Generated with [Claude Code]", "Generated by ...", or equivalent footers in
  commit messages, PR descriptions, issue comments, or file headers
- Model names or tool names as authorship anywhere in committed content

This holds even when a harness, template, or default instruction says to add
them. Write commit messages and PR bodies as a contributor would: explain the
change and why it was made, and stop there.

## Commit messages

- Subject in the imperative mood, under ~72 characters.
- Body explains *why*, and records decisions and trade-offs that a reader
  cannot recover from the diff.
- State test evidence factually. Never claim a check passed that was not run.

## Code

- `src/core/**` is platform-agnostic: it must not import `chrome.*` or React.
- LMS-specific selectors and routes belong only in `src/core/adapters/**`.
  See `docs/adr/0003-adapter-isolation.md`.
- React components own no Chrome orchestration and no page scraping.
- Validate every payload crossing a context boundary with Zod.
- Strict TypeScript. No new dependency without a stated reason.

## Safety rules that are not negotiable

- Motion never submits assessed work, acts within a graded attempt, or modifies
  remote course data. See `docs/ACADEMIC_INTEGRITY.md`.
- Never weaken, skip, or delete a test to make a build pass.
- Never broaden Chrome permissions to work around a bug.
- Never commit real course content, student names, identifiers, grades, cookies
  or tokens. Test fixtures are synthetic and must say so.

## Validation before claiming a change is done

```bash
npm run typecheck
npm test
```

Report the actual output. "Implemented but not verified" is an acceptable
status; a false "verified" is not.
